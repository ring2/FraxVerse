# 设计稿与PRD覆盖差距审计报告

> 审计日期：2026-05-01
> 审计范围：FraxVerse-V2-AllPages.html 设计稿 vs PRD(00-综合PRD文档.md) + DD-08(前端交互模块.md) + TRACE-MATRIX.md
> 审计触发：用户发现设置页50+项配置严重遗漏

---

## 一、核心结论

**追溯机制存在三大盲区，导致设计稿（以及DD-08）大面积遗漏PRD需求。**

| 盲区 | 根因 | 影响 |
|------|------|------|
| 盲区1：追溯颗粒度太粗 | TRACE-MATRIX只追踪"功能模块"，不追踪"功能点内的子项" | 设置页50+配置项整体被1条T-030覆盖 |
| 盲区2：DD→设计稿无追溯 | 追溯链止于DD，从DD到设计稿/代码无二次验证 | DD写了但设计稿可以随便画 |
| 盲区3：Hermes消息系统零覆盖 | PRD定义了完整的推送体系，但全链路无追踪 | 所有微信推送功能无法实现 |

## 四、Hermes消息推送系统—— 全链路零覆盖

这是最严重的遗漏，影响范围远超设置页。

### PRD定义的推送体系

| 推送事件 | 优先级 | PRD位置 | DD覆盖 | 设计稿覆盖 |
|----------|--------|---------|--------|-----------|
| Agent精选结果 | 高 | L782-813 | ❌ 无 | ❌ 无 |
| 开仓推送 | 高 | L816-823 | ❌ 无 | ❌ 无 |
| 平仓推送 | 高 | L836-848 | ❌ 无 | ❌ 无 |
| 风控告警 | 最高 | — | ❌ 无 | ❌ 无 |
| 舆情事件 | 高 | — | ❌ 无 | ❌ 无 |
| 每日复盘报告 | 低 | L851-876 | ❌ 无 | ❌ 无 |
| 策略异常 | 最高 | — | ❌ 无 | ❌ 无 |
| 开盘前复核 | — | — | ❌ 无 | ❌ 无 |
| **Hermes基础服务** | — | L2503-2511 | ❌ 零覆盖 | ❌ 零覆盖 |

### 影响链

Hermes缺失 → 以下功能无法实现：
1. 参数变更审批（T-175标记✅但实际依赖Hermes） → 参数变更无法确认
2. 交易确认推送 → 建议模式下用户无法收到待确认订单
3. 止损/止盈触发通知 → 用户无法及时知道止损被执行
4. 风控告警推送 → 最高优先级通知无法送达
5. 复核结果推送 → 开盘前复核结果无法送达

**严重程度：P0** — 这是跨模块基础设施，所有依赖推送的功能都被阻塞

## 五、TRACE-MATRIX追溯盲区分析

### 5.1 颗粒度问题

| 追溯项 | 覆盖范围 | 实际需求点 | 盲区 |
|--------|---------|-----------|------|
| T-030 首次启动引导 | 1条 | Step1+Step2+Step3 + 异步任务 + system_config写入 | Step细节全漏 |
| 设置页相关 | 0条 | 12分类50+项 | **完全不在矩阵中** |
| Hermes推送 | 0条 | 8种推送事件 + 基础服务 | **完全不在矩阵中** |

### 5.2 ✅标记不实

| 追溯项 | 标记 | 实际情况 |
|--------|------|---------|
| T-014 配置热更新 | ✅ | PRD要求Redis pub/sub推送，DD-00实现为60秒轮询，机制偏离 |
| T-175 人工审批 | ✅ | 依赖Hermes推送微信，但Hermes零定义，实际不可实现 |

### 5.3 追溯链断裂

```
PRD需求 → TRACE-MATRIX(颗粒度粗) → DD文档(写了但可能偏离) → [断裂] → 设计稿(无追溯) → [断裂] → 代码(无追溯)
```

问题：DD到设计稿、设计稿到代码之间完全没有追溯验证机制。

## 八、总结

| 指标 | 数量 |
|------|------|
| 设置页遗漏配置项（已修复） | 38+ |
| 其他页面遗漏功能点 | 30+ |
| 完全缺失的页面 | 1（SetupPage） |
| 全链路零覆盖的模块 | 1（Hermes推送） |
| TRACE-MATRIX遗漏的追溯项 | 60+ |
| ✅标记不实的追溯项 | 2（T-014, T-175） |

**根因一句话**：追溯机制只管了"PRD→DD有没有写"，没管"DD→设计稿画没画对"和"DD里每个功能点的子项够不够细"。

设置页的遗漏只是冰山一角——Hermes推送系统整个被遗漏才是最大的定时炸弹。
