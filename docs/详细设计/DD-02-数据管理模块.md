## 1. 模块概述

### 1.1 职责边界

本模块负责：

- A股基础数据采集与存储（股票列表、日K线、技术指标）
- 资金流向数据采集
- 宏观经济数据采集
- 热点新闻采集与分类
- 数据同步调度（每日收盘后全量同步、盘中新闻轮询）
- 数据质量监控与自动修复
- 板块数据维护

**不负责**：

- 策略计算（见 DD-03）
- 实时行情推送（miniQMT行情服务直供，本模块仅做日K归档）
- Agent新闻分析（Agent从本模块读取数据，见 DD-04）

### 1.2 依赖关系

```
DD-02 数据管理模块
  ├── 依赖 PostgreSQL — 全部数据存储
  ├── 依赖 Redis — 行情缓存 + 采集锁 + 热点新闻缓存
  ├── 依赖 AKShare — 免费数据源（行情/资金流/个股新闻）
  ├── 依赖 miniQMT/xtdata — 行情补充（可选）
  ├── 依赖 APScheduler — 定时调度
  ├── 复用 StockAgent — 新闻采集器架构（HotNewsSource基类 + 5源并发采集）
  └── 被依赖 — DD-03策略引擎 / DD-04 Agent / DD-06风险监控
```

## 2. 核心数据模型

### 2.1 数据库表设计

#### 2.1.1 stocks 表 — A股基本信息

```sql
CREATE TABLE stocks (
    code            VARCHAR(10)     PRIMARY KEY,       -- 股票代码，如 600519.SH
    name            VARCHAR(20)     NOT NULL,           -- 股票名称
    industry        VARCHAR(30),                        -- 所属行业
    market          VARCHAR(10)     NOT NULL,           -- SH/SZ/BJ
    list_date       DATE,                               -- 上市日期
    is_st           BOOLEAN         NOT NULL DEFAULT FALSE,  -- 是否ST
    is_suspended    BOOLEAN         NOT NULL DEFAULT FALSE,  -- 是否停牌
    updated_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- 部分索引：只索引有价值的行
CREATE INDEX idx_stocks_st ON stocks(is_st) WHERE is_st = TRUE;
CREATE INDEX idx_stocks_suspended ON stocks(is_suspended) WHERE is_suspended = TRUE;
CREATE INDEX idx_stocks_industry ON stocks(industry);

COMMENT ON TABLE stocks IS 'A股基本信息表，约5000行';
```

**伪代码**：

```
# 幂等性：是
function get_klines(params: KlineQuery) -> KlineResponse:
    # 1. 参数校验
    [ASSERT] params.stock_code matches pattern "^\d{6}\.(SZ|SH|BJ)$"
    if params.limit > 500 then params.limit = 500 end if
    if params.limit < 1 then params.limit = 120 end if

    # 2. 查询数据库
    query = [DB] SELECT * FROM daily_klines
            WHERE stock_code = params.stock_code
              AND adjust_flag = params.adjust
    if params.start_date then query.AND(trade_date >= params.start_date) end if
    if params.end_date then query.AND(trade_date <= params.end_date) end if
    query.ORDER BY trade_date DESC LIMIT params.limit

    klines = query.execute()

    # 3. 补充股票名称
    stock = [DB] SELECT name FROM stocks WHERE code = params.stock_code

    return KlineResponse(stock_code=params.stock_code, stock_name=stock.name,
                         items=klines.reverse())  # 前端需要时间正序
end function
```

#### 4.3.4 HotNewsCollector 主采集器（并发采集 + 降级）

```
# ============================================================
# 核心采集器：并发采集5个金融源 + 独立个股新闻
# fork 自 StockAgent HotNewsCollector，增加:
#   1. 每源独立降级（连续3次失败→5分钟跳过）
#   2. 存储层 MongoDB→PostgreSQL
#   3. 双写: Redis缓存(前端实时展示) + PG持久化(Agent分析)
# ============================================================

class FraxVerseNewsCollector:
    """碎片宇宙新闻采集器"""

    # 注册的5个金融热点源
    SOURCE_CLASSES = [
        CLSSource,
        WallstreetcnSource,
        GelonghuiSource,
        Jin10Source,
        XueqiuSource,
    ]

    # 个股新闻采集器（独立）
    stock_news_collector = AKShareStockNewsCollector()

    async function collect() -> dict:
        """
        执行一次完整新闻采集

        流程:
        1. 并发采集5个金融热点源
        2. 采集AKShare个股新闻（股票池中的标的）
        3. 新闻去重 + 分类 + 关联标的
        4. 双写: Redis缓存 + PG持久化
        """
        # === 1. 并发采集5个金融热点源 ===
        sources = [cls() for cls in self.SOURCE_CLASSES]
        tasks = [self._fetch_source_with_fallback(source) for source in sources]
        results = await asyncio_gather(*tasks, return_exceptions=True)

        # 统计
        source_stats = {}
        all_hot_news = []  # 热点新闻（PG入库用）
        for source, result in zip(sources, results):
            if isinstance(result, Exception):
                [LOG] ERROR "新闻源采集异常" source = source.name error = str(result)
                source_stats[source.name] = {"count": 0, "status": "error"}
                self._record_source_failure(source.name)
            elif isinstance(result, dict):
                items = result.get("items", [])
                source_stats[source.name] = {
                    "count": len(items),
                    "status": "success"
                }
                # 缓存到Redis（前端实时展示，TTL=2h）
                [REDIS] SET "hot_news:{source.name}" = json_dumps(items) WITH TTL 7200

                # 转换为PG入库格式
                for item in items do
                    all_hot_news.append({
                        source: source.name,
                        source_display: source.display_name,
                        category: source.category,
                        title: item.title,
                        content: None,  # 热点新闻只有标题，无正文
                        url: item.url,
                        published_at: now(),  # 热点新闻无精确发布时间，用采集时间
                        hot_score: item.hot,
                        extra: item.extra or {},
                        tags: [],
                        related_stocks: [],
                        is_hot: False  # 后续计算
                    })
                end for
            end if
        end for

        # 关闭HTTP客户端
        for source in sources do
            await source.close()
        end for

        # === 2. 采集AKShare个股新闻 ===
        # 从股票池取当前关注标的
        pool_stocks = [DB] SELECT stock_code FROM stock_pool
                       WHERE status = 'active' LIMIT 50
        if len(pool_stocks) > 0 then
            stock_news = await self.stock_news_collector.fetch_for_stocks(
                stock_codes=[s.stock_code for s in pool_stocks],
                limit_per_stock=5
            )
            all_hot_news.extend(stock_news)
            source_stats["akshare"] = {"count": len(stock_news), "status": "success"}
        end if

        # === 3. 新闻后处理 ===
        processed = self._process_news(all_hot_news)

        # === 4. 批量入库PG ===
        saved_count = self._save_to_pg(processed)

        [LOG] INFO "新闻采集完成" stats = source_stats total = saved_count
        return {source_stats: source_stats, total_saved: saved_count}
    end function


    # ---- 单源采集 + 降级逻辑 ----
    async function _fetch_source_with_fallback(source: HotNewsSource) -> dict:
        """
        采集单个源，带降级逻辑

        降级规则:
        - 先检查该源是否已被标记不可用（连续3次失败）
        - 不可用则跳过本次采集
        - 采集成功则清除失败计数
        - 采集失败则递增失败计数
        """
        # 检查源是否被降级
        fail_count = [REDIS] GET "news_source_fail:{source.name}"
        if fail_count is not None and int(fail_count) >= 3 then
            [LOG] INFO "新闻源降级跳过" source = source.name fail_count = fail_count
            return {"items": [], "skipped": True, "reason": "source_downgraded"}
        end if

        # 执行采集
        try:
            items = await source.fetch()
            # 成功→清除失败计数
            [REDIS] DEL "news_source_fail:{source.name}"
            return {"items": items}
        except as e:
            # 失败→递增计数
            new_count = [REDIS] INCR "news_source_fail:{source.name}"
            [REDIS] EXPIRE "news_source_fail:{source.name}" 900  # 15分钟重置
            [LOG] WARNING "新闻源采集失败" source = source.name
                   error = str(e) fail_count = new_count

            if new_count >= 3 then
                [LOG] ERROR "新闻源已降级，后续将跳过" source = source.name
                # 同时更新data_source_status
                [REDIS] HSET "data_source_status:{source.name}" = {
                    available: false,
                    reason: str(e),
                    checked_at: now()
                }
                [REDIS] EXPIRE "data_source_status:{source.name}" 300
            end if
            raise  # 向上抛出，让外层统计
        end try
    end function


    # ---- 记录源失败（手动触发失败时也调用）----
    function _record_source_failure(source_name: str):
        new_count = [REDIS] INCR "news_source_fail:{source_name}"
        [REDIS] EXPIRE "news_source_fail:{source_name}" 900
        if new_count >= 3 then
            [LOG] ERROR "新闻源已降级" source = source_name fail_count = new_count
        end if
    end function


    # ---- 新闻后处理：去重 + 分类 + 关联标的 + 热度计算 ----
    function _process_news(raw_news: list<dict>) -> list<dict>:
        """
        处理原始新闻列表:
        1. URL去重（跳过PG中已存在的URL）
        2. 关键词分类标签
        3. 关联股票提取
        4. 热度计算
        5. 热点关键词更新
        """
        # 1. URL去重
        existing_urls = set(
            [DB] SELECT url FROM news
            WHERE published_at >= today() - interval '1 day'
            AND url IS NOT NULL
        )
        unique_news = [n for n in raw_news
                       if n.url and n.url not in existing_urls]

        # 2-4. 分类 + 关联 + 热度
        for news in unique_news do
            text = (news.title or "") + " " + (news.content or "")

            # 分类标签
            if not news.tags or len(news.tags) == 0 then
                news.tags = classify_news(text)
            end if

            # 关联股票
            if not news.related_stocks or len(news.related_stocks) == 0 then
                news.related_stocks = extract_related_stocks(text)
            end if

            # 热度计算: 源热度分 + 关键词热度 + 关联标的热度
            keyword_heat = 0
            for tag in news.tags do
                keyword_heat += [REDIS] ZSCORE "hot_keywords:{today()}" tag or 0
            end for
            news.hot_score = (news.hot_score or 0) + int(keyword_heat)
            news.is_hot = news.hot_score >= 15  # 热度分≥15标记为热点

            # 更新热点关键词
            for tag in news.tags do
                [REDIS] ZINCRBY "hot_keywords:{today()}" 1 tag
            end for
        end for

        return unique_news
    end function


    # ---- 批量入库PG ----
    function _save_to_pg(news_list: list<dict>) -> int:
        """批量UPSERT到PostgreSQL，URL去重"""
        if len(news_list) == 0 then return 0 end if

        # 过滤掉无URL的新闻（无法去重）
        news_with_url = [n for n in news_list if n.url]
        news_without_url = [n for n in news_list if not n.url]

        # 有URL的: UPSERT (UNIQUE(url)约束)
        if len(news_with_url) > 0 then
            [DB] INSERT INTO news (source, source_display, category, title, content,
                                    url, published_at, tags, related_stocks,
                                    is_hot, hot_score, extra)
            VALUES (news_with_url_batch)
            ON CONFLICT (url) DO UPDATE SET
                hot_score = GREATEST(news.hot_score, EXCLUDED.hot_score),
                is_hot = EXCLUDED.is_hot OR news.is_hot,
                tags = CASE WHEN jsonb_array_length(EXCLUDED.tags) > 0
                           THEN EXCLUDED.tags ELSE news.tags END
        end if

        # 无URL的: 直接INSERT（不冲突）
        if len(news_without_url) > 0 then
            [DB] INSERT INTO news (source, source_display, category, title, content,
                                    url, published_at, tags, related_stocks,
                                    is_hot, hot_score, extra)
            VALUES (news_without_url_batch)
        end if

        return len(news_list)
    end function
end class
```

```
# 新闻分类（简单关键词匹配，不用LLM，与V1.0逻辑一致）
function classify_news(text: string) -> list<string>:
    tags = []
    keyword_map = {
        "policy": ["政策", "规划", "补贴", "调控", "扶持", "监管"],
        "earnings": ["财报", "业绩", "营收", "利润", "同比增长", "年报", "季报"],
        "ipo": ["IPO", "上市", "首发", "科创板", "北交所"],
        "merger": ["并购", "重组", "收购", "合并", "借壳"],
        "macro": ["GDP", "CPI", "PMI", "降息", "降准", "LPR", "MLF", "逆回购"],
        "tech": ["AI", "芯片", "新能源", "光伏", "半导体", "算力", "大模型"],
        "international": ["美股", "美联储", "加息", "贸易", "制裁", "关税", "脱钩"],
        "fund": ["基金", "北向", "南向", "外资", "ETF", "融资融券"]
    }

    for category, keywords in keyword_map do
        for kw in keywords do
            if kw in text then
                tags.append(category)
                break  # 每个分类只匹配一次
            end if
        end for
    end for

    if len(tags) == 0 then tags = ["general"] end if
    return tags
end function


# 从文本提取关联股票
function extract_related_stocks(text: string) -> list<string>:
    related = []

    # 1. 正则提取股票代码（6位数字）
    code_matches = regex_findall(r"(?:^|\s|,|，)(\d{6})(?:\s|,|，|$)", text)
    for code in code_matches do
        normalized = normalize_stock_code(code)
        if [DB] SELECT EXISTS(SELECT 1 FROM stocks WHERE code = normalized) then
            related.append(normalized)
        end if
    end for

    # 2. 匹配股票名称（内存缓存stocks表，避免每次查库）
    #    启动时加载到内存，每日刷新
    all_stocks = get_stocks_name_cache()  # dict {name: code}
    for name, code in all_stocks do
        if name in text and code not in related then
            related.append(code)
        end if
    end for

    return related
end function
```

```
function check_data_quality(trade_date: date) -> QualityReport:
    report = QualityReport(date=trade_date, issues=[])

    # 1. 行情断更检查：当天有交易的股票是否有K线记录
    total_stocks = [DB] SELECT COUNT(*) FROM stocks WHERE is_st = FALSE AND is_suspended = FALSE
    kline_stocks = [DB] SELECT COUNT(DISTINCT stock_code) FROM daily_klines WHERE trade_date = trade_date
    missing_ratio = (total_stocks - kline_stocks) / total_stocks

    if missing_ratio > 0.05 then
        report.issues.append("行情缺失率{missing_ratio*100:.1f}%，超过5%阈值")

        # 自动补全：重新采集缺失股票的数据
        auto_repair_missing_klines(trade_date)
    end if

    # 2. 异常值检查：涨跌幅超过±20%（排除ST和新股）
    outliers = [DB] SELECT stock_code, close, prev_close
               FROM daily_klines k1
               JOIN daily_klines k2 ON k1.stock_code = k2.stock_code
               WHERE k1.trade_date = trade_date
                 AND k2.trade_date = prev_trade_date(trade_date)
                 AND ABS((k1.close - k2.close) / k2.close) > 0.20
                 AND k1.stock_code NOT IN (SELECT code FROM stocks WHERE is_st = TRUE)
    if len(outliers) > 0 then
        report.issues.append("{len(outliers)}只股票涨跌幅异常(>20%)")

        status = check_data_source_availability(source)

        COUNT(*) FILTER (WHERE ma5 IS NULL) * 100.0 / COUNT(*) as ma5_null_rate,
```

## 6. 异常处理

### 6.1 错误码定义

| 错误码 | HTTP | 含义 | 触发场景 |
|:-------|:-----|:-----|:---------|
| 40501 | 409 | 同步任务正在执行 | 重复触发同步 |
| 40502 | 502 | 所有数据源不可用 | AKShare+miniQMT均超时 |
| 40503 | 500 | 数据格式异常 | AKShare返回格式变更 |
| 40504 | 404 | 股票代码不存在 | 查询不存在的代码 |
| 40505 | 400 | 日期范围无效 | startDate > endDate |
| 40506 | 429 | API限频 | 请求超过60次/分钟 |
| 40507 | 503 | 全部新闻源不可用 | 5个金融热点源均降级，AKShare个股新闻也失败 |
| 40508 | 502 | 指定新闻源不存在 | news_sources同步时指定了未注册的source_id |

### 6.2 异常场景处理

| 场景 | 处理策略 |
|:-----|:---------|
| AKShare接口变更 | 捕获异常→记录日志→尝试miniQMT→标记akshare不可用→告警 |
| miniQMT未连接 | 跳过miniQMT数据源，仅用AKShare（日志提示） |
| 数据库写入超时 | 重试1次→仍超时则跳过该批次→记录失败日志 |
| Redis不可用 | 实时行情降级为直接查数据库，新闻缓存跳过仅写PG，性能下降但功能可用 |
| 新闻URL重复 | UPSERT忽略（ON CONFLICT），不报错 |
| 股票代码格式混乱 | normalize_stock_code统一处理，异常格式记录日志跳过 |
| 单个新闻源采集失败 | 递增`news_source_fail:{source}`计数，不影响其他源并发采集 |
| 新闻源连续3次失败 | 标记该源降级，后续周期跳过，15分钟后自动重试 |
| 全部5个金融源降级 | 仅保留AKShare个股新闻降级运行，记录ERROR日志，前端显示"热点新闻暂不可用" |
| 财联社API限频/封IP | 捕获HTTP 429→该源标记失败→其余4源正常→30分钟后重试 |
| 雪球cookie失效 | cookie_resp获取新cookie→重试1次→仍失败则标记xueqiu不可用 |
